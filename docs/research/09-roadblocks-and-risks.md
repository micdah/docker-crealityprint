# 09 — Roadblocks and risks (consolidated)

Date: 2026-11-21 (updated after the printer tests and the remaining hands-on tests, docs 11–12). This file pulls together the blockers and risks from docs 01–08 and 11–12 and resolves the places where they disagree. Each entry links to the doc that has the evidence. Tags: **[V]** verified (seen in source or tested hands-on), **[I]** inferred.

**Bottom line: there are no hard blockers.** Creality Print V7.3.1 runs in `baseimage-selkies:debiantrixie` with one extra apt package (`libwebkit2gtk-4.1-0`) and orcaslicer's recipe ([07](07-hands-on-baseline.md)) [V]. Everything below is about robustness, UX and maintenance.

## Severity legend

| Severity | Meaning |
|---|---|
| **High** | Breaks the image or loses user data if ignored. Must be handled in the first build. |
| **Medium** | A user-visible gap or a likely future breakage. Handle or document it in v1. |
| **Low** | Polish, edge cases, or things to watch. |

## Risk register

| # | Risk | Sev. | Evidence | Mitigation |
|---|---|---|---|---|
| R1 | **PUID/PGID change on an existing `/config` gives a black screen.** lsio's `lsiown` only fixes ownership of the `/config` directory itself, not what is inside it, so labwc/Wayland can't start. | High | [05 T3](05-settings-persistence.md) [V] | Add our own `init-*` oneshot that runs `chown -R abc:abc` on `/config/.config`, `/config/.local`, `/config/.cache` and `/config/.XDG` when their owner differs from `abc`. |
| R2 | **Autostart/menu are copied into `/config` only once.** A later image that changes the launch command never reaches existing users. | High | [01 §4](01-baseimage-selkies.md), [05 hands-on](05-settings-persistence.md) [V] | Point `/defaults/autostart{,_wayland}` and the menus at a **stable, image-owned wrapper** (e.g. `/usr/local/bin/crealityprint`), and never change that path. All launch flags and env vars go in the wrapper. |
| R3 | **Asset naming churn.** v7.3.0 shipped 3 AppImages, the name pattern has changed several times (`Ubuntu2404-V…` → `…-x86_64-Release`), and some releases are flagged prerelease while creality.com treats them as current. | High (CI) | [03 §2.3](03-creality-print.md), [08 §2.1](08-prior-art.md) [V] | Build from `/releases/tags/${VERSION}`, not `latest` (orcaslicer's pin is a no-op, see [02](02-docker-orcaslicer.md)). Strict regex `^CrealityPrint-V[0-9.]+-x86_64-Release\.AppImage$`. Take the highest build number and **fail if nothing matches**. Verify the sha256 from the GitHub asset `digest`. |
| R4 | **Data-epoch directory (`…/Creality Print/7.3/`).** A future epoch bump (7.4/8.0) may start with an empty config unless the app's migration code covers it. The 7.3 migration is hard-coded from `7.0`/`6.0`. | Medium | [05 §4](05-settings-persistence.md) [V source, V hands-on 7.0→7.3] | Persist all of `/config`, never only the versioned subdir. Before shipping an image with a new epoch, run the T5-style migration test from [05](05-settings-persistence.md). Don't use `--datadir` (it disables migration) and don't symlink the data dirs (migration aborts). |
| R5 | **LAN printer discovery uses raw mDNS multicast (UDP 5353).** Docker's default bridge networking drops it, so printers aren't found automatically. Even with `network_mode: host`, a stateful host firewall (ufw/firewalld) drops the printer's unicast replies to the app's random UDP ports. | Medium | [11 §1, §7](11-printer-tests.md) [V with a real K1C] | **Default: bridge networking plus "Add by IP"** [V]. Status/control, G-code upload and the camera (both MJPEG and WebRTC) all work through Docker NAT. The IP dialog accepts IP octets only, so recommend a DHCP reservation. Optional auto-discovery: host networking plus a firewall rule (e.g. `ufw allow proto udp from <lan>/24 port 5353`), or macvlan. Both are **unverified** (macvlan was declined; this host has ufw). Printers can move from WS 9999 to TLS 443 after a firmware update, and the app follows by itself [V], so don't document fixed ports. |
| R5b | **Starting a print on a Creality OS printer always runs the printer's own prepare routine** (heat, home, wipe), even for a G-code file with no start code. A file without end code then **leaves the heaters on**. The file list's "Start printing" has no confirmation dialog, and the send dialog's "Print Calibration" toggle defaults to ON. | Medium (safety, docs/CI) | [11 §6](11-printer-tests.md) [V, K1C heated to 224 °C / 50 °C] | Never automate a start-print test against a real printer. Upload-only ("Send Only") is the safe end-to-end check. Add a user-docs note. |
| R6 | **Variable fonts crash the app** (the bundled static FreeType vs variable fonts such as Adwaita Sans; CP #607/#621/#637). | Medium | [03 §5](03-creality-print.md), [08 §2.2](08-prior-art.md) [V issues] | The base currently has **no** Adwaita/variable UI font; `fc-match sans-serif` = Noto Sans Regular [V, checked in `crp-research:baseline`]. Don't install `fonts-adwaita`/`fonts-cantarell`. Add a CI smoke test that the main window appears. |
| R7 | **Base-image ABI drift (pango/glib).** Orca had to leave Ubuntu resolute because pango 1.57 crashed its Preferences dialog, and CP #567 shows the same crash. The CP AppImage takes GTK, pango, webkit and gstreamer from the host. | Medium | [01](01-baseimage-selkies.md), [02 §5](02-docker-orcaslicer.md), [08](08-prior-art.md) [V] | Use `debiantrixie`, **pinned by a release tag/digest** with Renovate bumps. Smoke-test each bump: open Preferences, slice, open Preview. |
| R8 | **Installing `vainfo` breaks the stream on Intel Gen9 (UHD 630).** It re-arms the base's i965 probe, giving a black picture, and users can't override it. | Medium | [04 hands-on](04-gpu-acceleration.md) [V] | Never put `vainfo` in the image. Install it ad hoc for debugging only. |
| R9 | **`HARDEN_DESKTOP=true` does not disable file transfer** (it only hides the UI; the API still allows upload and download). | Medium (security) | [06 R6](06-file-transfer.md) [V] | Document `SELKIES_FILE_TRANSFERS=none` and `PASSWORD` / auth at a reverse proxy. Without either, anyone who can reach the port can read and write `/config/Desktop`. |
| R10 | **Third-party (Google/Apple) cloud login** opens `xdg-open` inside the container, and the OAuth callback goes to the container's `localhost:13666`. Without an in-container browser it can't complete. | Medium | [03 §7.4](03-creality-print.md) [V source; not tested] | v1: document **email/QR login** (embedded WebKit dialog). Optional: install Firefox (orcaslicer does, via Mozilla's apt repo) plus a `gio mime` handler. That adds about 250 MB, so decide in the build session. |
| R11 | **Creality Cloud device identity may use the MAC address** (`__CXY_DUID_`). A re-created container gets a new MAC and could appear as a new device or force a re-login. | Low | [03 §7.4](03-creality-print.md) [I] | Document an optional fixed `mac_address:` in compose. Verify with a real login. |
| R12 | **Unsaved-project auto-backup lives in `/tmp`**, so it's lost on re-create. | Low | [05 T0](05-settings-persistence.md) [V] | Document it. Optionally mount a tmpfs or a volume, or symlink `/tmp/crealityprint_model` into `/config`. Untested; symlinks may upset the app. |
| R13 | **No arm64 build** (no aarch64 AppImage; only a v7.3.0 aarch64 flatpak). | Low | [03](03-creality-print.md), [07](07-hands-on-baseline.md) [V] | Ship amd64 only. Unlike orcaslicer, don't add `Dockerfile.aarch64`. |
| R14 | **Image size about 5 GB** (base 3.7 GB, webkit + gstreamer 424 MB, extracted AppImage 538 MB). | Low | [07 §10](07-hands-on-baseline.md) [V] | Acceptable (orcaslicer is 6.9 GB). **Drop the optional gstreamer packages** (`-gl`, `-libav`, `-plugins-bad`, `-tools`, `-x`), which saves about 250 MB (4.77 GB). Both K1C camera paths (MJPEG and WebRTC) work without them, because the app decodes with its own bundled libs ([11 §4](11-printer-tests.md)) [V]. |
| R15 | **The upstream `dev` branch redesign of baseimage-selkies** (Selkies serves HTTP itself; no nginx, pulse or de services) could change the downstream contract. | Low | [01 §1](01-baseimage-selkies.md) [V] | Pinning the base protects us. Watch for `dev` being promoted, then re-check the `/defaults/autostart*` semantics. |
| R16 | **The startup update check can't be disabled.** On Linux it only opens a download URL and never self-replaces. | Low | [03 §7.5](03-creality-print.md) [V source] | Harmless in a container. Optionally seed `app.skip_version` (effect not verified, because no prompt appeared in any run). |
| R17 | **`AUTO_GPU=false` doesn't disable the GPU** on single-GPU hosts, contrary to the docs. | Low | [04 hands-on](04-gpu-acceleration.md) [V] | To run without the GPU, don't mount `/dev/dri`. |
| R18 | **NVIDIA and AMD are untested.** CP has open "blank 3D view on NVIDIA" bugs, and lsio needs driver 580+ plus the toolkit. | Low/unknown | [04 §5–6](04-gpu-acceleration.md) [desk only] | Document as best effort. Ask NVIDIA users for feedback. |
| R19 | **Intel GPU hang after slicing on Mesa 26.x** (CP #604, `INTEL_DEBUG=noccs`). | Low (today) | [04 §6.2](04-gpu-acceleration.md) [V issue; not reproduced on Mesa 25.0.7] | Re-test when the base moves to Mesa 26. Keep `INTEL_DEBUG=noccs` as a documented workaround. |
| R20 | **The first watcher prototype (`ft-watcher`) was broken.** A word-splitting bug on "Creality Print" meant `single_instance` was never set, so each upload started a *second* app window that covered the first. That made it look as if the plate was replaced (06 R7 misread this). | Low (fixed) | [12 §1](12-remaining-hands-on.md) [V] | Use the `ft-watcher2` design. It calls the running app's single-instance D-Bus method directly, so STLs are **added** to the current plate and unsaved work survives; 3MFs get the app's own "save changes?" prompt. It falls back to starting the app if none is running. Keep it opt-in. Dropped models land at the bed centre and can overlap, so the docs should say to press *Arrange*. |
| R22 | **The client needs a secure context.** Plain `http://<lan-ip>:3000` gives a black page; the clipboard also needs HTTPS. | Low (docs) | [12 §2](12-remaining-hands-on.md) [V] | Document `https://<host>:3001` or a TLS reverse proxy as the only supported access. |
| R23 | **Helper scripts must use `DISPLAY=:0`** (the app's Xwayland display), not the `:1` in the container env. | Low | [12 §1.5](12-remaining-hands-on.md) [V] | Set it explicitly in every script that talks to the app (watcher, healthchecks). |
| R21 | **AGPL-3.0 licence.** | Low | [03 §3](03-creality-print.md) [V] | Redistributing the unmodified AppImage is fine. Link the exact upstream tag/source in the README and image labels. If we ever patch the binary, publish that source. |

## Contradictions between the docs, and how they were resolved

| Topic | Disagreement | Resolution |
|---|---|---|
| webkit 4.0 vs 4.1 (decides Trixie vs Noble) | [02](02-docker-orcaslicer.md)/[01](01-baseimage-selkies.md) left it open | **4.1**: `ldd` on the 7.3.1 binary lists `libwebkit2gtk-4.1`/`libsoup-3.0`, and the app runs on Trixie ([07 §4](07-hands-on-baseline.md)) [V]. Trixie is confirmed. |
| Copy orcaslicer's apt set as-is (Firefox, `libmspack0`, `libwx-perl`, `localedef`) | [02 §8](02-docker-orcaslicer.md) says copy; [07](07-hands-on-baseline.md) says not needed | **Not needed to run** [V]: `libmspack` is bundled, and AppRun forces `LC_ALL=C`, so `localedef` has no effect. Firefox is only for third-party OAuth and external links (R10), so it's a build-session decision. Skip `libwx-perl` (orcaslicer-specific). |
| More libs (`libthai0`, `libbz2`, `libosmesa6`, `libsecret`, …) from [08](08-prior-art.md)'s list | Prior-art lists vs `ldd` | `ldd` on the 7.3.1 AppImage on Trixie showed **only** webkit/jsc/soup missing ([07 §4](07-hands-on-baseline.md)) [V]. The rest are already in the base or bundled. Keep `ldd … \| grep 'not found'` as a build-time guard rather than installing speculatively. |
| `privacyInfo.json` meaning | [05](05-settings-persistence.md) desk: "accepting the privacy policy" | **Hands-on**: `{"check":false}` is the *User Experience Improvement Program* (telemetry) opt-out written by "Cancel" [V]. It's safe to ship as a default (doc 05 was corrected). |
| GPU i965 auto-switch | [04](04-gpu-acceleration.md) desk: can never fire (no `vainfo`) | True for our image, and it's actively harmful if `vainfo` is added (R8) [V]. |
| `GDK_BACKEND=x11` | Copied from orcaslicer, not A/B tested | Keep it [I]. Native Wayland GTK + wxGL is known-fragile upstream, and both Wayland mode (app on Xwayland) and X11 mode work with the GPU [V]. |
| `--single-instance` CLI flag | [06](06-file-transfer.md) desk: verified in source | The 7.3.1 binary **rejects** it [V, 06 R7]. Setting `"app.single_instance": true` works only if set before the app starts. The robust route is calling the running instance over D-Bus directly ([12 §1.5](12-remaining-hands-on.md)) [V]. |
| Watcher "replaces the plate" | [06 R7](06-file-transfer.md) | **Wrong.** It was a second app instance covering the first. Correct forwarding *adds* STLs to the plate and keeps unsaved work ([12 §1](12-remaining-hands-on.md)) [V]. |
| Drag-and-drop not automatable | [06 R4](06-file-transfer.md) | It **can** be automated with CDP `Input.dispatchDragEvent` with real file paths. It uploads files and folders to `/config/Desktop` ([12 §3](12-remaining-hands-on.md)) [V]. |
| Session D-Bus in Wayland mode | [01](01-baseimage-selkies.md): none started | GTK/the app reach a session bus through **X11 autolaunch on `:0`** (`dbus-x11`) [V, 06 R7]. Single-instance forwarding works. The system bus stays disabled (orcaslicer's `svc-dbus` override) with no visible problems [V]. |

## Tested since the first pass ([11](11-printer-tests.md), [12](12-remaining-hands-on.md))

- Real K1C: add-by-IP, status, G-code upload, MJPEG and WebRTC camera, printer kept across re-create, all on bridge networking. Auto-discovery fails in bridge mode and, on this ufw host, in host mode too.
- Clipboard: text both ways and images browser → app work over HTTPS.
- Drag-and-drop: automated via CDP. It works.
- Long session (29 min, CPU and GPU): `/dev/shm` and memory flat, so no sign of #142.
- Upload watcher with unsaved work: safe with the `ft-watcher2` design.

## Still untested

- Creality Cloud login (email/QR) and whether the MAC address matters (the user chose to skip it).
- Auto-discovery with host networking on a host without a stateful firewall; macvlan (declined).
- K2-family printers. The firmware version on the test K1C wasn't recorded (the app doesn't show it).
- NVIDIA and AMD GPUs.
- One manual real-OS drag-and-drop, a Firefox clipboard check, and a multi-hour idle run (does the +240 MB WebKit step repeat?).
